您的下一位客戶可能不是透過搜尋引擎找到您。相反，他們會問 AI 助理：「我該如何做某事？」、「哪個選項最適合像我這樣的人？」、「直接幫我處理好」，然後一個智慧體就會找到答案、衡量各種選項，並代表他們採取行動。越來越多時候，決定客戶是否選擇您的關鍵時刻，發生在模型的回應之中——早在真人看到您的首頁之前。

這個由智慧體構成的受眾群體已經到來：據我們統計，目前不到一半的 HTML 頁面請求​來自人類。雖然並非所有機器請求都來自代表人類的智慧體，但這一比例正在迅速增長；答案引擎、購物助理和研究工具將決定哪些企業能被發現並獲得推薦。過去，「可被發現」意味著在搜尋結果頁面上排名靠前；現在，它意味著能被引導客戶的智慧體「找到、讀懂，並有信心地推薦」。

傳統的衡量指標（如人類點擊量和頁面瀏覽量）已無法反映全貌。我們與許多網站擁有者進行了溝通，他們面對充斥著 AI 機器人的存取記錄，卻完全不瞭解這些機器人是否有能力使用其網站，或者是否會向使用者推薦其產品和服務。我們聽到了兩個主要問題：

  • 智慧體真的能使用我的網站嗎？
  • 我有被推薦嗎？

為了幫助網站擁有者回答這些問題，我們將​先前關於 Agent Readiness 的研究成果整合到了 Cloudflare 儀表板中，並新增了 Answer Engine Optimization（AEO，答案引擎最佳化）工具。這些工具將智慧體視為網站的核心使用者群，向您展示智慧體如何看待您的網站，以及您的網站被推薦的頻率。

這是巨大的機遇，且門檻不高，因為大多數網站尚未針對這類使用者進行最佳化。就像早期 SEO 獎勵那些為搜尋引擎打造的網站一樣，現在為智慧體打造的網站也將獲得回報。那些容易被找到、讀取和信任的網站，就是智慧體會推薦的網站。

Diagnostics：您的網站準備好迎接智慧體了嗎？

Diagnostics 是 Agent Readiness 中的技術檢查工具。它會以智慧體讀取網站的方式來掃描您的網站：它會判斷是否允許進入、是否能發現您的內容、擷取一份乾淨的機器可讀副本，並找出它可以呼叫的介面。 

人類只需要載入您的首頁，而智慧體則依賴您的 robots.txt、您的 sitemap（網站地圖）、您的回應標頭、內容的 Markdown 版本，以及用於驗證和工具的中繼資料。

Diagnostics 會針對一個主機名稱執行這些檢查，並將結果匯總到一個展示「智慧體就緒度」的檢視中，涵蓋從「未就緒」到「完全原生支援智慧體」的各個層級。每項檢查的結果分為通過、失敗或中立，並附帶關於其重要性的說明以及包含具體請求與回應詳情的證據記錄。

以下檢查按所需投入程度分組，讓您知道從哪裡開始：

  • 快速見效：大多數網站都缺乏的高影響力基礎項目，包括可供爬蟲讀取的 robots.txt、XML 網站地圖、AI 爬蟲規則，以及向智慧體提供乾淨的 Markdown 內容
  • 技術基礎：下一層，包括說明您的內容可以如何被使用的 Content Signals（內容訊號）、API 目錄、連結標頭，以及智慧體登入說明
  • 進階整合：智慧體原生功能，包括 OAuth 探索、MCP（模型情境通訊協定）和 A2A (Agent2Agent) 智慧體卡片、技能索引、Web Bot Auth 和 WebMCP
  • 商務：新興的智慧體支付標準，包括 x402（經典 HTTP 402 Payment Required 狀態碼的延伸）、ACP（智慧體商務通訊協定）、UCP（通用商務通訊協定）和 AP2（智慧體支付通訊協定）。此項目目前僅供參考，不會計入您的分數。

每一項建議的改善都附有下一步行動。當有 Cloudflare 功能可以提供協助時，會有「在 Cloudflare 中設定」的連結直接導向該設定頁面，例如開啟 Markdown for Agents 或受管理的 robots.txt。至於其他所有項目，則有「複製智慧體提示詞」按鈕，列出您的編碼智慧體需要建構的內容。完成變更並重新掃描後，您就能看到檢查標記變為綠色。

AEO：AI 助理是否在推薦您？

Diagnostics 告訴您智慧體能否讀取您的網站。而 AEO 分頁則告訴您接下來發生的事：當客戶在 AI 助理中提出與您產業類別相關的問題時，它會推薦您，還是推薦競爭對手？這不像搜尋排名那樣可以隨時查詢。由於沒有展示次數統計或錯失點擊報告，一旦助手推薦了競爭對手而非您，您就會在毫無察覺的情況下痛失這筆交易。

我們會從您的網站推斷您的產業（例如健康與健身）和類別（例如運動服飾），並用可能的客戶提示詞來探測主流助理（目前是 Anthropic 的 Claude 和 OpenAI 的 GPT），觀察它們如何回應。我們將這些提示詞設計成模擬真實世界的探索情境，在您的類別範圍內詢問推薦、產品比較和一般建議。透過觀察模型如何回答這些逼真的查詢，您可以獲得以下指標：

  • 引用率 (Citation Rate)：在該類別的回答中，引用您的網站作為來源的比例
  • 顯著度 (Prominence)：當您被引用時，您的內容佔回答的多大比重，以及出現的位置有多靠前
  • 提及率 (Mention Rate)：助理在回答中提及您品牌的頻率，例如「Cloudflare」一詞出現在回應中的次數（無論 cloudflare.com 是否被列為來源）。將此數據與引用率一併解讀，可區分「品牌知名度」與「內容歸因」：若助理提及您的次數遠高於引用次數，代表您在其「雷達」上，但尚未贏得引用——這是一個具體且可針對性改善的缺口
  • 聲量佔有率 (Share of Voice)：您的引用數相對於競爭對手的比例，讓您清楚看到在那些您未能勝出的提示詞中，誰才是贏家

為了評估 AI 模型如何看待您的市場地位，我們會先為各產業與類別建立基準線，再對特定網站進行評分。我們會向 AI 助理提出該類別下可能的提示詞（過程中不指定您的品牌），並記錄哪些網站被引用、出現位置及其顯著程度。

我們並非在每次網站擁有者執行掃描時才重新查詢模型，而是針對每個類別執行一次基準調查，並將該資料集重複用於該領域的所有帳戶。預先計算這些資料集帶來三大優勢：

  • 零延遲：結果從快照中即時載入，不需要等待即時的模型查詢。
  • 降低運算開銷：在類別層級彙整查詢，避免在數千次掃描中重複呼叫 AI。
  • 產業契合度評分：重用基準資料集讓我們能對應出哪些品牌經常被一同提及，進而推導出「產業契合度」分數，衡量 AI 助理是否將您的網站與真正的競爭對手歸類在一起。

AI 助理幾乎不會用完全相同的方式回答同一個問題兩次。為了考量這種變異性，我們透過 Cloudflare AI Gateway，跨不同模型對各助理進行多次提示。接著，我們讀取客戶實際看到的回應（包含回答文字及其引用的來源），並從中提取多重訊號。 

我們的評估不僅關注您的網站是否被提及，還包括是否被列為來源、引用出現的早晚，以及最終回答中有多少實質內容源自您的網站。在需要精準判斷之處，由 Workers AI 負責繁重的解讀工作：其在我們自有的基礎架構上原生執行，讀取每則回覆並為您的引用與提及表現評分。我們亦採用精確的文本分析，而非讓模型自我評分。綜合這些手段，我們將數十次零散的回應轉化為可操作的指標。透過抽象化多模型查詢與評估流程，這個工具會提供各項指標，無須您自行建置評估框架。

除了回答分析外，「AI 營運商活動 (AI Operator Activity)」檢視展示了各營運商（如 OpenAI、Google 等）對您網站的實際爬取與推薦流量：誰在讀取您的內容、誰將訪客導回您的網站，以及他們在過程中遇到的錯誤（如 403 blocked、404 dead link）。其中最值得採取行動的模式是：某營運商爬取了您數千個頁面卻未帶來任何訪客，這意味著它使用了您的內容，卻未將客戶引導至您的網站。

由於這些數據專屬於您的網站，您可以進行實驗、重新掃描，並針對那些能為您帶來業務的具體問題，衡量各項舉措的影響。

認識您的另一群受眾

直到現在，評估智慧體的影響多半靠猜測：用 grep 搜尋記錄推斷訪客來源，或是手動輸入提示詞觀察聊天機器人有沒有提到您。但有了 Agent Readiness 與 AEO，您便能獲得足以採取行動的數據。而且由於這些請求真實流經 Cloudflare，這些工具會盡可能進行實際測量而非僅估算，並且其效果會隨時間推移不斷提升。 

協助您看清誰在造訪您的網站，並決定如何依循您的規則與之互動，這正是我們一貫的使命。智慧體只是最新的受眾群體，而那些讓自己容易被智慧體發現、理解並信任的企業，將會獲得推薦。Agent Readiness 讓您查明自己是否名列其中，以及若尚未達標該如何改進。

準備好確認 AI 智慧體是否正在為您帶來客戶了嗎？前往儀表板的「概觀」分頁，讓您的網站達成智慧體就緒，並申請 AEO 可見性的提前存取。
